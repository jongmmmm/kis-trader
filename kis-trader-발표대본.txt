------------------------------------------------------------
[슬라이드 3] 프로젝트 개요 & 기술 스택
------------------------------------------------------------

KIS-TRADER는 한국투자증권이 제공하는 Open API를 활용해서
주식 매매를 자동으로 수행하는 웹 애플리케이션입니다.

모의투자 모드와 실전투자 모드를 런타임에 전환할 수 있고,
4가지 매매 전략과 AI 분석 기능,
그리고 실시간 경매 알림을 제공합니다.

기술 스택을 보시면,

백엔드는 Flask 3.1을 메인 프레임워크로 사용하고,
Flask-SQLAlchemy로 ORM 처리,
SQLite를 데이터베이스로,
APScheduler로 백그라운드 작업을 관리합니다.

데이터 처리와 머신러닝 쪽에서는
pandas로 시계열 데이터를 다루고,
ta 라이브러리로 기술적 지표를 계산하며,
scikit-learn의 RandomForest로 가격 예측 모델을 구현했습니다.

API 통신은 requests 라이브러리로 KIS API를 호출하고,
SSE, 즉 Server-Sent Events로 실시간 알림을 구현했습니다.

운영 모드는 모의투자와 실전투자로 나뉘는데,
각 모드별로 별도의 API 키와 계좌번호를 사용하며,
런타임에 자유롭게 전환이 가능합니다.

[슬라이드 4] 전체 아키텍처 & 파일 구조
------------------------------------------------------------

파일 구조를 보시겠습니다.

run.py가 애플리케이션 진입점이고, 포트 6001번에서 실행됩니다.
app.py는 Flask 앱 팩토리 패턴으로 앱을 생성하는 역할을 합니다.
config.py에는 API 키, URL, 스케줄러 간격 등 환경 설정이 들어있고,
db.py는 SQLAlchemy 인스턴스를 정의합니다.

models.py에는 5개의 DB 모델이 정의되어 있고,
kis_api.py가 한국투자증권 API를 래핑하는 7개 함수를 제공합니다.
scheduler.py에서 4개의 백그라운드 Job을 등록하고,

routers 폴더에는 5개의 Blueprint가,
strategies 폴더에는 매매 전략 모듈과 AI 분석기가 있습니다.

오른쪽 아키텍처 흐름도를 보시면,
브라우저 클라이언트가 Flask 웹서버에 접속하고,
서버는 REST API를 통해 잔고 조회, 시세 조회, 전략 관리 등을 제공합니다.

그 아래에 APScheduler가 백그라운드에서
전략 실행, 경매 체크, 알림 만료, ML 재학습을
주기적으로 수행하고,

최종적으로 KIS Open API를 호출해서
실제 현재가 조회, 일봉 데이터 조회, 주문 실행, 잔고 확인을 합니다.


------------------------------------------------------------
[슬라이드 5] 핵심 모듈: KIS API 래퍼
------------------------------------------------------------

kis_api.py는 이 프로젝트의 핵심 모듈입니다.
한국투자증권 Open API의 복잡한 호출을
깔끔한 Python 함수로 추상화했습니다.

총 7개의 함수가 있는데, 하나씩 살펴보겠습니다.

첫 번째, get_token 함수는 OAuth 토큰을 발급하고 갱신합니다.
DB에 토큰을 캐시해서, 만료 5분 전에 자동으로 재발급합니다.
매번 새로 발급받지 않아도 되니 API 호출이 최적화됩니다.

두 번째, get_current_price는 종목의 현재가를 조회합니다.
가격, 등락률, 거래량, 고가, 저가, 시가를 딕셔너리로 반환합니다.

세 번째, get_daily_ohlcv는 일봉, 주봉, 월봉 데이터를 가져옵니다.
매매 전략의 지표 계산에 필수적인 함수입니다.

네 번째, place_order는 실제 매수/매도 주문을 실행합니다.
지정가와 시장가를 모두 지원하고,
모의투자와 실전투자에서 서로 다른 tr_id를 자동으로 매핑합니다.

나머지 get_index_price, get_volume_rank, get_balance는 각각
코스피/코스닥 지수 조회, 거래량 상위 종목, 계좌 잔고 조회 기능입니다.

핵심은 _credentials 함수로 paper/real 모드를 자동 분기하고,
_headers 함수에서 tr_id를 매핑하며,
KisToken 모델로 토큰을 DB에 캐싱한다는 점입니다.

[슬라이드 6] 데이터 모델
------------------------------------------------------------

models.py에는 5개의 테이블이 정의되어 있습니다.

첫 번째, Strategy 모델은 매매 전략 정보를 저장합니다.
전략 유형은 ma, rsi_macd, condition, ml 네 가지가 있고,
params 필드에 JSON 형태로 전략별 파라미터를 유연하게 저장합니다.
is_active로 활성/비활성을 제어하고, mode로 모의/실전을 구분합니다.

두 번째, Order 모델은 주문 이력을 기록합니다.
매수/매도 구분, 상태 관리,
그리고 trigger 필드로 자동 주문인지 경매를 통한 수동 주문인지 구분합니다.
KIS에서 받은 실제 주문번호도 저장합니다.

세 번째, AuctionAlert 모델이 특히 중요한데요,
경매 시간에 AI가 분석한 결과를 저장합니다.
ai_confidence는 0에서 100까지의 신뢰도,
ai_score는 마이너스 100에서 플러스 100까지의 종합 점수,
ai_summary에 판단 근거 텍스트,
ai_factors에 팩터별 상세 분석 결과가 JSON으로 들어갑니다.
사용자가 buy, sell, pass 중 하나를 결정하면 user_decision에 기록됩니다.

네 번째, PortfolioSnapshot은 포트폴리오 스냅샷,
다섯 번째, KisToken은 OAuth 토큰 캐싱용 모델입니다.


------------------------------------------------------------
[슬라이드 7] 매매 전략 엔진
------------------------------------------------------------

strategies 폴더에는 BaseStrategy 추상 클래스를 상속한
4가지 매매 전략이 구현되어 있습니다.

모든 전략은 should_buy와 should_sell이라는
통일된 인터페이스를 사용합니다.

첫 번째, MA 전략은 이동평균선 교차를 기반으로 합니다.
기본적으로 5일과 20일 이동평균선을 사용하며,
골든크로스가 발생하면 매수, 데드크로스가 발생하면 매도합니다.

두 번째, RSI+MACD 전략은 두 가지 지표를 결합합니다.
RSI가 30 이하 과매도 구간에서 MACD가 상향 돌파하면 매수,
RSI가 70 이상 과매수 구간에서 MACD가 하향 돌파하면 매도합니다.
ta 라이브러리를 사용해서 지표를 계산합니다.

세 번째, 조건식 전략은 사용자가 직접 조건을 정의합니다.
예를 들어 "등락률이 3% 이상이면 매수" 같은 조건을
indicator, operator, value 구조로 설정할 수 있습니다.
크다, 작다, 이상, 이하, 같다 연산자를 지원합니다.

네 번째, ML 전략은 scikit-learn의 RandomForest를 사용합니다.
MA5, MA20, MA60, RSI, MACD, 거래량 비율, 수익률 등
8개의 피처로 다음날 상승 여부를 예측합니다.
매일 새벽 3시에 자동으로 재학습하며,
매수 확률이 65% 이상이면 매수, 35% 이하이면 매도합니다.

그리고 BaseStrategy에는 공통 기능으로
손절 마이너스 5%, 익절 플러스 10% 자동 관리가 내장되어 있습니다.


------------------------------------------------------------
[슬라이드 8] RAG AI 분석기
------------------------------------------------------------

ai_analyzer.py는 8가지 팩터를 종합 분석하는 AI 엔진입니다.

각 팩터는 마이너스 100에서 플러스 100까지의 점수를 매기고,
서로 다른 가중치로 합산합니다.

이동평균 추세가 가중치 20%로 가장 높습니다.
골든크로스, 데드크로스, 정배열 역배열, 60일선 위치를 분석합니다.

RSI, MACD, 거래량이 각각 15%의 가중치를 갖습니다.
RSI는 과매수 과매도 구간과 추세를,
MACD는 히스토그램 전환과 매수매도세를,
거래량은 평균 대비 비율과 방향성을 봅니다.

모멘텀과 변동성이 각각 10%,
캔들 패턴이 8%, 당일 등락이 7%를 차지합니다.

판단 로직은 간단합니다.
가중 합산 점수가 20점 이상이면 매수,
마이너스 20점 이하이면 매도,
그 사이면 관망을 추천합니다.

신뢰도는 점수의 절대값과 팩터 간 방향 일치도를
결합해서 최대 95%까지 산출합니다.

마지막으로 판단 근거를 자연어 요약 텍스트로 자동 생성하는데,
현재가, 긍정 요인 수, 부정 요인 수, 핵심 근거를 포함합니다.

[슬라이드 9] 스케줄러 & 자동화
------------------------------------------------------------

scheduler.py에서는 APScheduler를 사용해 4개의 백그라운드 Job을 관리합니다.
타임존은 Asia/Seoul로 설정되어 있습니다.

첫 번째, run_strategies는 60초마다 실행됩니다.
장중 시간, 즉 9시부터 15시 30분 사이에만 동작하고,
경매 시간에는 실행하지 않습니다.
활성화된 전략을 순회하면서 지표를 계산하고,
보유 종목의 손절 익절을 먼저 체크한 뒤,
매매 신호가 발생하면 주문을 실행하고 기록합니다.

두 번째, check_auction_and_alert는 30초마다 실행됩니다.
경매 시간, 즉 아침 8시부터 9시, 오후 3시 20분부터 30분에만 동작합니다.
활성 전략별로 AI 분석을 수행하고,
AuctionAlert를 생성해서 SSE로 브라우저에 실시간 푸시합니다.

세 번째, expire_undecided_alerts는 60초마다
만료된 미결정 알림을 자동으로 pass 처리합니다.

네 번째, retrain_ml_models는 매일 새벽 3시에
ML 전략 종목의 120일 데이터로 모델을 재학습합니다.

------------------------------------------------------------

routers 폴더에는 5개의 Flask Blueprint가 있습니다.

시세 조회 시 전략에 등록된 종목 외에도

Orders 라우터는 주문 내역 조회를 담당하고,

Settings 라우터는 모의투자 실전투자 모드 전환과
토큰 캐시 초기화 기능을 제공합니다.

[슬라이드 11] 실시간 경매 알림 (SSE)
------------------------------------------------------------

auction.py는 이 프로젝트에서 가장 흥미로운 부분 중 하나입니다.
Server-Sent Events를 활용한 실시간 경매 알림 시스템입니다.

구조를 보시면,
_sse_clients라는 리스트에 연결된 클라이언트의 Queue를 관리합니다.
threading.Lock으로 동시성을 보호하고,
각 클라이언트는 최대 20개의 메시지를 버퍼링하는 Queue를 갖습니다.

브라우저가 /api/auction/stream에 접속하면 SSE 스트림이 열리고,
30초마다 ping을 보내서 연결을 유지합니다.
새로운 알림이 발생하면 broadcast 함수가
모든 클라이언트 큐에 메시지를 넣어 실시간 푸시합니다.

오른쪽의 반자동 의사결정 흐름을 보시면,
스케줄러가 경매 시간에 AI 분석을 수행하고,
그 결과로 AuctionAlert를 생성합니다.
이것이 SSE로 브라우저에 실시간 전달되면,
사용자가 화면에서 매수, 매도, 패스 중 하나를 선택합니다.
매수나 매도를 선택하면 바로 KIS API를 통해 주문이 실행되고,
Order 레코드가 자동으로 생성됩니다.
미결정 알림은 만료 시간이 지나면 자동으로 pass 처리됩니다.

이 구조의 핵심은 완전 자동이 아닌 "반자동" 매매라는 점입니다.
AI가 분석하고 추천하지만, 최종 결정은 사용자가 내립니다.


------------------------------------------------------------
[슬라이드 12] 시스템 흐름도
------------------------------------------------------------

이제 전체 시스템의 흐름을 세 가지로 나눠서 정리하겠습니다.

왼쪽은 자동매매 흐름입니다.
장중 9시부터 15시 30분 사이에,
APScheduler가 60초마다 전략을 실행합니다.
활성 전략을 조회하고, KIS API로 데이터를 가져온 뒤,
먼저 보유 종목의 손절 익절을 체크합니다.
그 다음 전략 엔진의 should_sell, should_buy를 순서대로 확인하고,
신호가 발생하면 주문을 실행하고 DB에 기록합니다.

가운데는 경매 알림 흐름입니다.
경매 시간에 30초마다 AI 분석을 수행하고,
8가지 팩터를 가중 합산해서 매수 매도 관망을 판단합니다.
그 결과를 SSE로 브라우저에 보내고,
사용자가 결정하면 주문이 실행되는 구조입니다.

오른쪽은 ML 모델 학습 흐름입니다.
매일 새벽 3시에 ML 전략 종목을 대상으로
120일치 OHLCV 데이터를 가져오고,
8개 피처를 엔지니어링한 뒤,
